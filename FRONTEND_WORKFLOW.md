# Работа с интерфейсами в Codex

Проект: `frontend/`, React + Vite. Дизайн и компоненты описаны в `frontend/DESIGN.md` и `frontend/COMPONENTS.md`. Сначала прочитайте правила проекта; сохраняйте 3D-трубу и текущие изменения.

1. Попросите: «Предложи три разные концепции экрана осмотра, сохраняя текущую трубу. Пока не меняй frontend».
2. В новом сеансе Codex попросите использовать `superdesign` и, если подключён, Doop. Superdesign: `superdesign login`; Doop: `codex mcp login doop`. Уточняйте стоимость до любых платных генераций.
3. Откройте ссылку на canvas, которую даст агент, и сравните варианты. В Doop откройте https://doop.design и создайте или выберите canvas, затем передайте его ссылку агенту.
4. Выберите вариант: «Беру второй вариант; сохрани его композицию и используй существующие токены».
5. Попросите: «Перенеси выбранную концепцию в компоненты проекта, сохраняя функциональность и данные API».
6. Запустите `cd frontend && npm run dev` или существующий Compose на http://localhost:18080. Попросите Codex через Playwright открыть страницу, проверить взаимодействия, консоль и снимки на 375 и 1440 px в обеих темах.
7. Попросите: «Используй Impeccable для critique и audit, затем исправь выявленные проблемы». При первом запуске доступен `/impeccable init`; проверьте существующий дизайн-контекст перед изменением. Hooks установлены в `.codex/hooks.json`: в Codex откройте `/hooks` и разрешите их, если приложение запросит подтверждение.
8. Попросите показать итог, снимки, diff и результаты `cd frontend && npm run verify`.

После установки skills и MCP перезапустите Codex, чтобы обновить список инструментов. Доступность Doop зависит от OAuth; Superdesign требует входа. Концепции и перенос в React требуют проверки агентом, автоматически готовый production-код не гарантируется.
