## Как проверялась точность?

Контрольное ВТД на дату прогноза у целевых труб в демо-наборе скрыто. Поэтому каждый сценарий
проверяется на исторической паре с тем же устройством задачи: модели обучаются без этой пары,
проверяются на ней, а затем финальные модели переобучаются вместе с ней.

| Сценарий | Валидационная пара | Сегментов |
| --- | --- | --- |
| Между обследованиями | соседи целевой трубы по нитке, 1250009490 и 1250011604: ВТД 06.07.2022 → ВТД 01.12.2023 | 55 |
| С ввода в эксплуатацию | труба 1250022871: ввод 2000 → первое ВТД 23.09.2018 | 525 |

Основная метрика — квадрат корреляции Пирсона r² между прогнозом и минимальной толщиной сегмента
по факту; вторая — MAE в миллиметрах.

## Какие проверки на устойчивость были?

Отрицательные результаты публикуются вместе с положительными:

- **Сдвиг одометра.** На валидации сдвиг прошлого пропуска оценивается по паре пропусков той же
  трубы. При ошибке сдвига ±1 м r² падает до 0,71–0,74, при выравнивании только по соседям — до
  0,29. У целевой трубы пропуска 2023 года нет, поэтому на ней стоит ждать меньше 0,75.
- **Труба без ВТД, строгий вариант.** Если исключить валидационную трубу из обучения целиком, r²
  падает до 0,05: позиции дефектов слабо переносятся между трубами.

## Как это воспроизвести?

```bash
cd ml && uv sync && uv run python -m pipetwin
```

Конвейер печатает таблицу метрик и пишет `artifacts/validation_report.csv`. Запуск детерминирован:
seed 42, версии в `ml/uv.lock`, `result.csv` совпадает байт в байт между запусками.

## Какие автоматические проверки проходят?

| Часть | Команда | Результат 16.11.2026 |
| --- | --- | --- |
| ML | `cd ml && uv run pytest && uv run ruff check src tests warehouse` | 9 тестов, ruff без замечаний |
| Backend | `cd backend && uv run ruff check . && uv run mypy . && uv run pytest` | ruff и mypy без замечаний, 159 тестов |
| Frontend | `cd frontend && npm run verify` | 36 правил проекта, типы, линтер, 400 тестов, сборка |

Тесты backend читают настоящие результаты конвейера: полноту прогноза, единственность ключей,
границы сегментов, приоритеты, экспорт `result.csv` целиком и сверку пар валидации. На Windows их
нужно запускать с `PYTHONUTF8=1`: без него Python читает файлы в системной кодировке.

Браузерные сценарии (`npm run e2e` при запущенном стенде) проверяют обе трубы, выбор сегмента
мышью и клавиатурой, связь с API, развёртку, очередь и CSV, восстановление после ошибки API,
отсутствие горизонтального переполнения, axe WCAG AA, reduced motion и работу без WebGL. Они
выполняются в Chromium; физические сенсорные устройства не проверялись.

## Чего эти числа не доказывают?

Точность на целевых трубах, покрытие P10–P90 и пользу очереди проверки для реальных шурфов. Это
описано в [ограничениях](limitations.md).
