# Как помощник исследует вопрос

Текущий HTTP-помощник использует PydanticAI и Codex Responses с моделью `gpt-6.1-sol`.
Статус миграции приведён в конце этой страницы; описание прежнего цикла ниже
сохранено до завершения перехода и не является спецификацией нового пути.
Числа вычисляют инструменты Python по обслуживаемому снимку. Модель получает выбранные
доказательства, формулирует следующий запрос инструмента или ответ инженеру.

**Читайте, если** подключаете помощника или проверяете происхождение ответа ·
**Связано:** [Запуск](running.md) · [API](api.md) · [Границы прогноза](limitations.md)

## Какие данные получает модель?

Первый пакет содержит выбранный сегмент: прогноз, квантили, номинал и доступные обследования
с датами. Контекст вопроса задаёт трубу, сегмент, снимок, дату прогноза, дату сравнения и диапазон.
Приложение сверяет контекст с текущим снимком до обращения к модели.

| Инструмент | Результат |
| --- | --- |
| `segment` | Один сегмент и его датированные наблюдения |
| `explanation` | Сохранённая декомпозиция, наблюдения, гипотезы и недостающие данные одного сегмента |
| `neighbors` | Выбранный сегмент и до двух соседей с каждой стороны |
| `priorities` | Место, равенства прогнозов, правило отбора, сводка трубы и первые пять кандидатов |
| `range_summary` | Количество, минимум, медиана, максимум и до пяти номеров сегментов выбранного диапазона |
| `validation` | До восьми исторических метрик, разбиения и статус отдельного архивного сравнения |

Все инструменты ограничены выбранной трубой. Они не принимают SQL, пути файлов или код.
Полный профиль, суточные ряды и таблица признаков не передаются модели. Суммарный пакет
доказательств ограничен 32 000 символами сериализованного JSON. История ограничена 12 сообщениями
и 24 000 символами; она передаётся как недоверенный контекст, а не источник фактов.

Карточка объяснения проверяется по ключу, дате, прогнозной и номинальной толщине. Эта сверка
не заменяет манифест обучения: совпадение итогового числа не доказывает идентичность всех
входных признаков. Неизвестная или несовместимая карточка вызывает ошибку.

## Как проходит исследование?

Прикладной модуль управляет циклом через структурированные ответы SDK. Модель выбирает
инструмент и номер сегмента; приложение проверяет запрос, выполняет инструмент и добавляет
результат с идентификатором `E1`, `E2` и далее. Допускаются четыре дополнительных вызова,
после чего модель должна ответить по имеющимся данным. Повтор одного инструмента для того же
сегмента отклоняется. Каждый шаг использует отдельный временный поток Codex и получает
накопленные ограниченные доказательства; нативные динамические инструменты SDK не используются.

Финальный структурированный ответ содержит до восьми утверждений со ссылками на текущие
доказательства. Сервер проверяет существование ссылок до выдачи текста. Эта проверка
не устанавливает смысловую правильность утверждения: модель всё ещё может неверно пересказать
источник. Проверка реальных ответов на инженерных вопросах требует отдельного прогона.

SDK работает в временной папке, с режимом read-only и запретом подтверждений. Shell,
Web search и просмотр изображений отключены. При API-ключе временная папка также служит
изолированным `CODEX_HOME`; ключ не записывается в постоянную конфигурацию пользователя.
Без ключа используется существующая авторизация и конфигурация локального Codex.

На процесс допускаются два одновременных исследования. Общий таймаут, включая ожидание
свободного места, составляет 110 секунд. Остановка запроса отменяет ожидающий вызов провайдера.
Ответ передаётся NDJSON: статусы и данные выдаются по ходу исследования, итоговый текст —
после завершения структурированного ответа. Это не поток токенов провайдера.

## Как включить Codex?

Для локальной разработки с существующей авторизацией Codex:

```bash
cd backend
uv sync --group llm
LANGUAGE_MODEL=codex uv run uvicorn app.main:create_app --factory --port 8000
```

Для контейнера задайте в локальном `.env` значения `LANGUAGE_MODEL=codex`, `LLM=true`
и `CODEX_API_KEY` с доступом к указанной модели. Затем:

```bash
LLM=true docker buildx bake
docker compose up -d --wait
```

Секрет не передаётся фронту. Вызовы модели используют учётную запись сервера и могут расходовать
её лимиты. Локальный стенд не имеет пользовательской авторизации и не предназначен для
публикации этого endpoint в открытый интернет.

При `LANGUAGE_MODEL=none` или `claude` инженерный помощник выдаёт явно обозначенную сводку
без LLM: выбранный прогноз и текущее ранжирование. Свободный анализ вопроса в этом режиме
недоступен. Если Codex включён, сбой провайдера выдаётся как ошибка, а не успешная сводка.

## Что проверяют тесты?

Тесты прикладного цикла проверяют выбор инструмента, ограничение данных, неизвестные ссылки,
неверные запросы и отмену. Интеграционные тесты читают реальные DuckDB/CSV и карточки, проверяют
HTTP NDJSON и отказ при устаревшем снимке. Провайдер заменяется только в тестах.
Платные вызовы, качество русского текста и фактическое время ответа модели этими тестами
не подтверждаются.

## Статус перехода на PydanticAI

Путь `LANGUAGE_MODEL=codex` использует PydanticAI 2.68 и `OpenAICodexModel` через Responses.
Старый адаптер Codex SDK сохранён для прежнего общего интерфейса, но HTTP-помощник использует
новый агентный цикл. API-ключ `CODEX_API_KEY` не авторизует новый Codex-провайдер: ему нужна
существующая авторизация Codex. Большие результаты SQL сохраняются как SQLite-артефакты;
модели возвращаются идентификатор, до пяти строк выборки и статистики всего результата.
Каталог возвращает колонки, типы, единицы и описания; неизвестные единицы обозначаются явно.

Доступны девять инструментов: `data_catalog`, `pipe_state`, `search_methodology`,
`explain_corrosion`, `query_data`, `render_chart`, `forecast_state`, `compare_pipes`,
`compose_dashboard`. SQL работает только на разрешённых аналитических представлениях,
с ограничением даты, времени выполнения и объёма результата. Полные таблицы и ряды идут
в интерфейс по ссылкам на артефакты; модель получает компактные результаты.

Сравнение включает паспорт, обследования, плотность дефектов, режимы и доступные прогнозы.
Историческое изменение средней стенки не считается локальной скоростью коррозии.
Начальный корпус методик содержит два проверенных первичных источника с областью применения
и ограничениями; поиск использует SQLite FTS5. Это ограниченный корпус, а не полная библиотека.

На `/dashboards` доступны сохранённые дашборды, на `/dashboards/:id` — конкретная версия.
Обновление повторяет сохранённые запросы и создаёт новую неизменяемую версию без обращения
к модели; доступны история и переход к предыдущим версиям. Таблицы в чате имеют пагинацию
по 100 строк. Графики используют числовые, временные и категориальные шкалы.

В рабочей области ассистент открывается отдельной панелью. Черновик и сообщения сохраняются
при закрытии панели в пределах открытой страницы. Автоматические проверки используют
PydanticAI TestModel и подмену потока только в браузерных тестах; живой Sol не проверялся.
