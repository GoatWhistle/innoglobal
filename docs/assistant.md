# Инженерный помощник

Панель чата в осмотре трубы. Помощник отвечает на вопрос о выбранной трубе и сегменте: каждое
утверждение в ответе ссылается на доказательство, которое вычислил инструмент приложения.
Модель сама числа не считает.

**Читайте, если** включаете помощника или проверяете, откуда взялся ответ · **Связано:**
[API](api.md) · [Безопасность](security.md) · [Ограничения](limitations.md)

---

## В каких режимах он работает?

| Режим | Настройка | Что умеет |
| --- | --- | --- |
| Сводка | `LANGUAGE_MODEL=none`, по умолчанию | Без языковой модели: прогноз выбранного сегмента на дату и его место в очереди проверки со ссылками на доказательства. Ответ помечен как сводка |
| Исследование | `LANGUAGE_MODEL=codex` | Агент PydanticAI на модели `gpt-6.1-sol` через Codex: сам выбирает инструменты, строит таблицы и графики, собирает дашборды |

Если исследование включено и провайдер не ответил, интерфейс показывает ошибку, а не подменяет её
сводкой.

## Какие инструменты есть у агента?

| Инструмент | Что возвращает |
| --- | --- |
| `data_catalog` | Таблицы, колонки, типы, единицы и описания аналитических представлений |
| `pipe_state` | Паспорт, обследования и прогноз выбранной трубы |
| `forecast_state` | Прогноз на дату: результат модели или сценарная оценка |
| `explain_corrosion` | Вклады признаков, наблюдения и гипотезы для сегмента |
| `compare_pipes` | Паспорта, обследования, плотность дефектов, режимы и прогнозы нескольких труб |
| `query_data` | Результат одного `SELECT` над представлениями только для чтения |
| `render_chart` | График по сохранённому результату запроса |
| `compose_dashboard` | Дашборд из графиков и таблиц этого разговора |
| `search_methodology` | Фрагменты справочного корпуса методик (SQLite FTS5) |

Большие результаты сохраняются как артефакты в `assistant.sqlite3`: модель получает идентификатор,
до пяти строк выборки и статистику, интерфейс — полную таблицу с пагинацией по 100 строк.
Историческое изменение средней стенки не выдаётся как локальная скорость коррозии. Корпус методик
небольшой: два первичных источника с областью применения и ограничениями.

## Какие ограничения стоят на цикле?

- Не больше 16 запросов к модели и 12 вызовов инструментов на вопрос; общий таймаут 180 секунд.
- Два исследования одновременно на процесс, остальные ждут.
- Пакет доказательств — до 32 000 символов JSON; история — последние 12 сообщений, она передаётся
  как недоверенный контекст, а не источник фактов.
- SQL: один `SELECT`, отдельная DuckDB в памяти, 5 секунд, 256 МБ, до 50 000 строк.
- Финальный ответ — список утверждений со ссылками `E1`, `E2`… Сервер отклоняет ответ, если
  ссылка не указывает на доказательство этого прогона. Смысловую точность пересказа эта проверка
  не гарантирует.

Ответ приходит потоком NDJSON: статусы и артефакты по ходу работы, текст — после завершения.

## Как включить модель?

Режиму исследования нужна действующая авторизация Codex на машине, где работает backend.
Проще всего запустить backend локально, а интерфейс — в Compose или через Vite:

```bash
cd backend
uv sync --group llm
LANGUAGE_MODEL=codex uv run uvicorn app.main:create_app --factory --port 8000
```

Для контейнера соберите backend с библиотеками LLM (`LLM=true` в `.env`) и задайте
`LANGUAGE_MODEL=codex`. Ключ остаётся на сервере и в интерфейс не передаётся. Вызовы расходуют
лимиты учётной записи сервера; у стенда нет пользовательской авторизации, поэтому не публикуйте
его в открытый интернет без прокси с авторизацией.

## Где хранятся дашборды помощника?

`compose_dashboard` сохраняет дашборд в `assistant.sqlite3` (том `assistant-state`). Он открывается
на `/dashboards/:id`. «Обновить» повторяет сохранённые запросы без обращения к модели и создаёт
новую неизменяемую версию; предыдущие версии доступны в истории.
