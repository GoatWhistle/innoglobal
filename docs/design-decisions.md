# Почему продукт использует эти правила

## Правила обслуживания прогноза

| Правило | Какой сбой предотвращает | Чем закреплено | Остаточный предел |
| --- | --- | --- | --- |
| DuckDB и CSV открываются только для чтения; снимок загружается при старте | Перезапись результатов при просмотре | DuckdbSnapshotSource, read-only mounts Compose | Для нового снимка нужен перезапуск |
| Идентификатор снимка учитывает все входные файлы | Несогласованная версия геометрии, признаков и прогнозов | SHA-256 в source.py | Не устанавливает версию кода обучения |
| Сетка 10 м, последний конец ограничен длиной профиля | Выход за фактическую трубу | targets.py, интеграционные тесты | Одометрическая привязка наследует правила подготовки |
| Первые ceil(10% N), сортировка по толщине и номеру | Случайный порядок при равенстве | inspection_priorities и тесты | При плоском прогнозе различия не установлены |
| Наблюдения, номинал, прогноз и квантили показаны раздельно | Принятие прогноза за факт | Отдельные поля API и легенда профиля | Скрытое контрольное ВТД отсутствует |
| Угловая форма в 3D, развёртке и SVG иллюстративна; минимум равен прогнозу API | Принятие нарисованной формы за измерение | Общая illustrativeThickness и постоянная подпись | Угловых измерений в источнике нет |
| Ошибка API даёт повтор запроса; фиктивные ответы отсутствуют | Незаметная подмена данных | QueryView и браузерный сценарий отказа | Кэшированный вид может оставаться при обновлении |
| Выбор и диапазон хранятся в URL | Потеря сегмента при прямой ссылке | useWorkspaceState | Число сегментов связано с текущим снимком |
| Координаты API проверяются перед преобразованием в tuple | Неполная координата в проекции | parseNetwork | Не заменяет геодезическую проверку источника |

Исторические пары выдаются отдельно от метрик выбранной модели. Сопоставление по всей серии
наблюдений, историческим трубам и датам не позволяет незаметно присоединить чужие точки.
Несогласованная серия имеет `source_mismatch` без точек и без вычисленных метрик;
интеграционные тесты закрепляют отрицательный результат. Архив не содержит манифест обучения,
поэтому совпадение с текущим разбиением не доказывает тождество выбранному модельному прогону.

Переключатели Segmented меняют цвет сразу и анимируют только нажатие.
Это исключает промежуточный низкий контраст при смене выбранного пункта.
Браузерная проверка axe выполняется также после переключения таблицы и графика.

Численные типы из DuckDB преобразуются в доменные dataclass на границе repository.
`Any` в адаптере обозначает значение драйвера до преобразования; в HTTP оно не передаётся.
Порты LLM и decision-model остаются необязательными зависимостями каркаса и не участвуют в прогнозе.

## Физическая сцена

Главный экран открывает выбранную трубу. Обзор сети доступен отдельно по `/overview`.
Материалы стали, сварных швов, опор и нефти перенесены из утверждённого каталога.
Три режима камеры, профиль, полоса сегментов и чертёж используют один segment_id из URL.
Выбор хранит идентификатор, а не индекс массива; координата конца трубы выбирает последний
сегмент. Клавиши 1/2/3 переключают камеры, стрелки и Home/End выбирают сегменты.

Иллюстративная угловая форма нужна для физического образа трубы. Она ограничена номиналом
и прогнозным минимумом; её нельзя использовать как карту дефектов. Эта оговорка видна рядом
со сценой. Замеры ВТД, прогноз и P10–P90 сохраняют собственные подписи.

Движок Three.js разделён на модули геометрии, материалов, камеры, проекции и ввода.
Типизированная граница связывает его с React и реальными строками API. При отказе контекста
ресурсы освобождаются, а резервные виды сохраняют выбор и численные данные.

Исключение `--dur-scene-cut` (1000 мс) относится только к редкому перелёту камеры.
Обычные элементы интерфейса его не используют. Клавиатура и reduced motion переключают
камеру сразу; числа не интерполируются. Скрытая вкладка приостанавливает отрисовку.

## Отдельная галерея инженерных представлений

Пять вариантов размещены в `/design/variants`, чтобы сравнивать способы работы с теми же
данными и сохранять доступ к основному интерфейсу. Профиль загружается один раз на уровне
страницы. Выбор и диапазон хранятся в URL через общий `entities/pipe/use-workspace-state`;
страница передаёт их представлениям как управляемые свойства. Существующий экран использует
тот же модуль через прежний экспорт.

Страница соединяет схему стенки, физическую сцену и варианты через слоты. Поэтому один
функциональный модуль не зависит от другого. Общие дорожки используют одну ось расстояния
и шкалу по полной трубе. Отсутствующее ВТД на конкретном участке оставляет пробел;
номинал подставляется только когда базой сравнения явно выбран паспорт.

Стальной материал нового продольного вида получен ортографическим рендером существующей
процедурной текстуры duppel. Он не кодирует измерения; прогноз задаётся отдельной полосой
по реальным сегментам. В галерее изображения служат снимками реализованных экранов,
интерактивные представления продолжают получать данные API.

## Совмещённый осмотр и сравнение

В «Осмотре участков» труба, профиль обследования, прогноз и знаковая разница используют один
диапазон и выбранный сегмент. Локальный режим следует за участком и показывает соседей; режим
всей трубы и выделение диапазона дают общий обзор. Выделенный диапазон сохраняется в URL.
Дата обследования управляет графиком, разницей, горизонтом и значением базы в правой панели.
При отсутствии ВТД используется явно подписанный паспортный номинал.

Общий ComparisonPanel используется и в отдельном столе сравнения. В совмещённом осмотре
наложение показывает оба источника целиком, чтобы не скрывать данные соседей. Подвижная
граница остаётся в отдельном столе сравнения. Компактная высота трубы и дорожек задана
существующими токенами; цветовые шкалы по-прежнему рассчитываются по всей трубе.

## Инструменты инженерного помощника

| Правило | Какой сбой предотвращает | Чем закреплено | Остаточный предел |
| --- | --- | --- | --- |
| Codex SDK, SMART=`gpt-6.1-sol`, структурированный цикл с четырьмя запросами инструментов | Загрузка всей таблицы в LLM и неограниченное исследование | Схема шагов, бюджет доказательств и тесты usecase | Каждый шаг заново передаёт ограниченный контекст |
| Порт объяснений возвращает JSON одной карточки; `JsonSchema` допускает `Any` внутри данных артефакта | Связывание прикладной логики с файловым форматом хранения | Проверка ключа, даты и толщин | Полный манифест обучения отсутствует |
| Ссылки утверждений проверяются по реестру текущих доказательств | Выдуманные идентификаторы источников | Тест неизвестной ссылки | Смысл утверждения автоматически не доказывается |
| Сводка без LLM обозначена явно; ошибка включённого Codex остаётся ошибкой | Подмена недоступного агента успешной генерацией | Offline-тест и потоковый код ошибки | Качество реальных ответов требует отдельной оценки |
