# Решения

Почему продукт устроен именно так: какой сбой предотвращает каждое правило, чем оно закреплено и
что остаётся за его пределами. Код написан без комментариев, поэтому неочевидные решения
объясняются здесь.

**Читайте, если** меняете поведение продукта · **Связано:** [Архитектура](architecture.md) ·
[Данные](data-contract.md)

## Как обслуживается прогноз?

| Правило | Какой сбой предотвращает | Чем закреплено | Остаточный предел |
| --- | --- | --- | --- |
| Обучение — отдельный сервис Compose; backend только читает готовый снимок | Перезапись результатов при просмотре, долгий старт API | `pipeline` завершается до старта `backend` | Новый снимок требует перезапуска backend |
| Снимок загружается целиком при старте и проверяется | Частично записанные или несогласованные файлы на экране | `ForecastCatalog`, интеграционные тесты | — |
| Идентификатор снимка — SHA-256 всех входных файлов | Смешение геометрии, признаков и прогнозов разных версий | `source.py` | Не фиксирует версию кода обучения |
| Сетка 10 м, последний сегмент обрезан длиной профиля | Сегменты за концом трубы | `targets.py`, тесты | Привязка наследует правила совмещения пропусков |
| Очередь — первые `ceil(10% N)` по толщине, при равенстве по номеру | Случайный порядок при одинаковом прогнозе | `inspection_priorities`, тесты | При плоском прогнозе порядок внутри равных условен |
| Наблюдения, номинал, прогноз и квантили — разные поля API и разные подписи на графике | Принятие прогноза за измерение | Схемы API, легенды графиков | — |
| Ошибка API показывается с повтором запроса, подстановочных данных нет | Незаметная подмена данных | `QueryView`, браузерный сценарий отказа | Закэшированный вид может остаться до обновления |
| Пары «прогноз — факт» сверяются с обучающим разбиением по всей серии | Присоединение чужих точек к графику валидации | Сверка ключей, дат и значений, тесты | Архив не содержит манифеста обучения |

## Почему форма стенки нарисована, а не измерена?

Прогноз задаёт только минимум в сегменте 10 м. 3D-труба, развёртка и сечение рисуют угловую форму,
чтобы инженер видел физический объект, но форма ограничена номиналом и прогнозным минимумом и
подписана как иллюстрация. Разрыв и поток в режиме осмотра — визуализация дефекта: утечка не
подтверждается прогнозом. Замеры ВТД, прогноз и P10–P90 всегда имеют собственные подписи.

## Как устроен рабочий экран?

- Выбор трубы, сегмента, режима и диапазона хранится в URL: прямая ссылка открывает тот же вид.
  Выбор хранит номер сегмента, а не индекс массива.
- Частый выбор сегмента применяется сразу; плавное движение оставлено для смены камеры и при
  прерывании начинается из текущего положения. Клавиатура и reduced motion переключают камеру сразу.
- Сцена Three.js разделена на геометрию, материалы, камеру, проекцию и ввод. При потере контекста
  WebGL ресурсы освобождаются, а Canvas2D и SVG показывают те же данные. Скрытая вкладка
  приостанавливает отрисовку.
- Признаки сегмента, медианы по трубе и глобальная важность показаны раздельно: интерфейс не
  приписывает глобальной важности влияние на конкретный прогноз.
- При смене сегмента прежние подробности убираются до ответа нового запроса, чтобы под заголовком
  нового сегмента не оказались данные старого.

## Как устроены дашборды?

Определения виджетов, их размещение и контекст дашборда хранятся раздельно. В localStorage лежат
версия схемы и ссылки, но не измерения: числа приходят из API при открытии. Повреждённая или
неизвестная версия не перезаписывается до явного сброса. Подробнее: [дашборды](dashboards.md).

## Как устроен помощник?

| Правило | Какой сбой предотвращает | Остаточный предел |
| --- | --- | --- |
| Числа считают инструменты приложения, модель получает компактные результаты | Пересказ всей таблицы моделью и выдуманные числа | Модель может неверно пересказать результат |
| Ссылки утверждений проверяются по реестру доказательств прогона | Выдуманные источники | Смысл утверждения автоматически не доказывается |
| Без модели — явно подписанная сводка; ошибка включённой модели остаётся ошибкой | Подмена недоступного агента правдоподобным ответом | Качество реальных ответов требует отдельной оценки |
| SQL — один `SELECT` в отдельной DuckDB в памяти с лимитами | Изменение данных и тяжёлые запросы | Лимиты подобраны для демо-объёма |

## Откуда карта?

Подложка лежит в репозитории и работает без сети: стенд должен открываться в закрытом контуре.
Страна, регионы, реки, озёра и крупные города — Natural Earth 10m, общественное достояние
(<https://www.naturalearthdata.com>). Дороги, водоёмы и населённые пункты вокруг месторождения —
OpenStreetMap, лицензия ODbL; подпись источников показана в панели карты. Слои упрощены заранее и
лежат в `frontend/src/features/pipeline-map/data/*.gen.ts`.

Карта рисуется в проекции Меркатора. Статичные слои один раз собираются в `Path2D` в мировых
координатах и выводятся одним преобразованием холста, поэтому масштаб и перетаскивание не
пересчитывают точки. Детальный слой месторождения включается только на близком масштабе.
