# Как связаны данные и прогноз

Приложение читает существующий DuckDB и CSV без перезаписи. Ключ прогноза: пара `id, segment_id`.

## Какие файлы нужны для просмотра?

| Источник | Содержание и использование |
| --- | --- |
| `warehouse/pipetwin.duckdb` | Паспорта, геометрия, сетка сегментов, обследования, режимы и журнал качества |
| `result.csv` | Организаторский прогноз: `id,segment_id,thickness_pred`, десятичная точка |
| `artifacts/uncertainty.csv` | Прогноз и квантили `p05,p10,p90,p95` по тому же ключу |
| `data/processed/predict_dataset.csv` | Численные признаки целевых сегментов; пустое или нечисловое значение отображается как отсутствие данных |
| `chart_data.json`, `data/processed/train_dataset.csv` | Отдельные архивные пары прогноз–факт и текущее историческое разбиение для проверки их совместимости |
| `artifacts/validation_report.csv` | Исторические метрики: `case,model,n,pearson_r2,mae` |
| `artifacts/feature_importance_case1.csv`, `feature_importance_case2.csv` | Глобальная важность CatBoost для кейса 1 и LightGBM для кейса 2, нормированная по сумме |

Все CSV читаются DuckDB с заголовком. Результат выдаётся в UTF-8. Типы полей API закреплены OpenAPI.
Исходные CSV в `data/` сохранены; `warehouse/sql/` задаёт преобразования слоёв raw, core, quarantine, mart.
Raw сохраняет номер строки, имя файла и момент загрузки. Приложение обслуживает готовый снимок, обучение не запускает.

## Какие трубы и даты используются?

| Кейс | Труба | Дата T | Сегменты | Длина, м |
| --- | --- | --- | --- | --- |
| Между ВТД | 1250022871 | 2023-12-01 | 525 | 5248,377450259997 |
| От ввода | 1250009583 | 2022-07-01 | 1475 | 14745,137813810006 |

Даты согласуются с конфигурацией поставленного ML-пайплайна и записью ответов менторов
от 14.11.2026, отметки 11:04–11:34. Контрольное ВТД этих кейсов не передано.
Первая труба имеет доступные ВТД 2018-09-23 и 2022-07-06; у второй исходного ВТД нет.

## Что значит номер сегмента?

`segment_id` начинается с нуля. Интервал: `[10 × segment_id, min(10 × (segment_id + 1), длина))`.
Конечная точка трубы включена в последний сегмент для навигации. Последние интервалы короче 10 м.
Расстояние в метрах от начала профиля. Высота в метрах, координаты трассы: долгота и широта
в градусах. API `/network` передаёт точки `[distance_m, longitude, latitude]`, прореженные с шагом 20 м,
с сохранением первой и последней точек. Карта использует локальную проекцию, без внешних тайлов.

## Где наблюдение, а где расчёт?

Паспортные диаметр, номинальная и браковочная толщины берутся из `core.pipe`.
Браковочный уровень служит справочной линией, не основанием для присвоения аварийного статуса.
Наблюдения берутся из `mart.ili_segment` только для допущенных обследований;
остаточная толщина, число дефектов и глубина относятся к соответствующему ВТД.
Отсутствие зарегистрированного дефекта не означает измерение всей стенки сегмента.
Правила смещения одометра находятся в `src/pipetwin/align.py`; прогнозы используют подготовленную сетку.

Толщины и квантили выражены в мм. P10 / P90 показывают результаты квантильных моделей,
а не откалиброванный доверительный интервал. Важность признака глобальная, не причинная.
Сечение схематично: минимум на 10 м не задаёт распределение дефектов по окружности.

## Что проверяется перед обслуживанием?

Снимок отклоняется при отсутствии необходимых файлов, недоступной БД, пропусках или дубликатах
прогноза, несовпадении ключей результата и сетки, нарушении порядка квантилей, нечисловом прогнозе
и прогнозе вне `(0, номинал]`. CSV результата сравнивается с прогнозом с допуском 0,0005 мм.
При отказе `/ready` возвращает 503 с причинами, продуктовые запросы возвращают `data_unavailable`.
Версия снимка вычисляется по содержимому файлов; отдельного подписанного реестра версий обучения нет.

Приоритет: первые `ceil(N × 0,10)` сегментов по паре `(толщина, segment_id)` по возрастанию.
Для 525 и 1475 сегментов это 53 и 148 записей. Это относительный список, не вероятность отказа.

## Как проверяются исторические пары?

API `/model/validation` возвращает `comparisons` отдельно от `metrics` выбранных моделей.
Источник пар: `chart_data.json`, поле `val`. Исходный генератор обучает этот прогон на `split=train`,
а пары берёт из `val_case1` и `val_case2`; для case1 он дополнительно применяет сглаживание.
Переобучение для просмотра не требуется.

Перед выдачей проверяются конечность и положительность значений, одинаковая длина массивов,
соответствие наблюдений строкам текущего `train_dataset.csv` с точностью 0,00051 мм,
уникальность ключей, целевые исторические трубы и даты разбиения.
Порядок строк CSV сохраняется. Идентификаторы присоединяются только при совпадении всей серии
наблюдений; отдельного манифеста обучения архив не содержит.

При совпадении `status=available`: точки содержат `pipe_id,segment_id,observed_mm,forecast_mm`,
а r² и MAE пересчитываются по этим округлённым парам. Первая серия: 55 пар, r²=0,3434524851,
MAE=0,3506181818 мм. Это отдельный прогон, не выбранный ens_blend с r²=0,5011 из отчёта.

У второй серии 525 пар, но её наблюдения расходятся с текущим разбиением. API возвращает
`status=source_mismatch`, пустые `points` и `null` для метрик сравнения. Интерфейс объясняет
причину отсутствия графика; таблица метрик выбранных моделей остаётся доступна.
