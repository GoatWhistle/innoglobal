# Данные и прогноз

Приложение читает готовый снимок: хранилище DuckDB и CSV, которые пишет конвейер. Ключ прогноза —
пара `id, segment_id`.

**Читайте, если** подключаете свои выгрузки или проверяете происхождение числа на экране ·
**Связано:** [Прогноз](model.md) · [API](api.md) · [Ограничения](limitations.md)

---

## Какие исходные данные нужны?

Выгрузки лежат в `data/` в CSV с заголовком. Демо-набор — обезличенные данные одного
нефтяного месторождения.

| Файл | Содержание |
| --- | --- |
| `pot_south.csv` | Паспорта 16 труб: местоположение, диаметр, номинальная и браковочная толщины, дата ввода |
| `altitudes_south.csv` | Профиль трассы: дистанция, высота, долгота и широта, около 20 тыс. точек |
| `vtd_south_train.csv` | Отчёты ВТД: дефекты, их положение, глубина и остаточная толщина, около 48 тыс. строк |
| `uzt_south.csv` | Точечные замеры ультразвуковой толщинометрии |
| `repcorr_south.csv` | Образцы-свидетели: условия экспозиции и скорость коррозии |
| `tech_mode_*.csv` | Суточный техрежим: давление, расход, обводнённость, температура, режим потока |

## Какие файлы читает приложение?

Пути указаны относительно `DATA_ROOT`: корня репозитория при локальном запуске или тома
`results` в Compose.

| Файл | Содержание и использование |
| --- | --- |
| `warehouse/pipetwin.duckdb` | Паспорта, геометрия, сетка сегментов, обследования, режимы, журнал качества |
| `result.csv` | Прогноз `id,segment_id,thickness_pred`, десятичная точка |
| `artifacts/uncertainty.csv` | Прогноз и квантили `p05,p10,p90,p95` по тому же ключу |
| `data/processed/predict_dataset.csv` | Признаки целевых сегментов; пустое значение показывается как отсутствие данных |
| `data/processed/train_dataset.csv`, `chart_data.json` | Пары «прогноз — факт» исторической валидации |
| `artifacts/validation_report.csv` | Метрики моделей: `case,model,n,pearson_r2,mae` |
| `artifacts/feature_importance_case1.csv`, `feature_importance_case2.csv` | Глобальная важность признаков, нормированная по сумме |
| `artifacts/explain_cards.jsonl`, `artifacts/degradation_curve.csv` | Карточки сегментов и кривая деградации для помощника |
| `docs/methodology/corpus.json` | Справочный корпус методик для помощника |

`ml/warehouse/sql/` задаёт преобразования слоёв raw, core, quarantine и mart. Слой raw сохраняет
номер строки, имя файла и момент загрузки.

## Что значит номер сегмента?

`segment_id` начинается с нуля и задаёт интервал
`[10 × segment_id, min(10 × (segment_id + 1), длина))` в метрах от начала профиля. Конечная точка
трубы относится к последнему сегменту, поэтому он может быть короче 10 м.

Высота задана в метрах, координаты трассы — долготой и широтой в градусах. `/network` отдаёт
точки `[distance_m, longitude, latitude]` с шагом 20 м и сохраняет первую и последнюю точки.
Карта строится в локальной проекции без внешних тайлов.

## Где наблюдение, а где расчёт?

- Паспортные диаметр, номинальная и браковочная толщины берутся из `core.pipe`. Браковочный
  уровень — справочная линия, а не основание для аварийного статуса.
- Наблюдения берутся из `mart.ili_segment` только для допущенных обследований. Отсутствие
  зарегистрированного дефекта не означает измерение всей стенки сегмента.
- Прогноз и квантили — расчёт конвейера. P10–P90 показывают квантильные модели, а не
  откалиброванный доверительный интервал.
- Угловая форма стенки в 3D, развёртке и сечении иллюстративна: прогноз задаёт только минимум
  на 10 м.

## Что проверяется перед загрузкой?

Снимок отклоняется, если:

- нет обязательного файла или хранилище недоступно;
- в прогнозе есть пропуски или дубликаты ключей, ключи не совпадают с сеткой сегментов;
- квантили нарушают порядок, прогноз нечисловой или вне интервала `(0, номинал]`;
- `result.csv` расходится с прогнозом снимка больше чем на 0,0005 мм.

При отказе `/ready` возвращает 503 с причинами, продуктовые запросы — код `data_unavailable`.
Идентификатор снимка — SHA-256 содержимого всех входных файлов; интерфейс показывает его рядом
с данными.

## Как выбирается приоритет проверки?

Первые `ceil(N × 0,10)` сегментов трубы по паре `(толщина, segment_id)` по возрастанию:
53 из 525 и 148 из 1475 в демо-наборе. Это относительный порядок для дополнительного осмотра,
а не вероятность отказа.

## Как показываются исторические пары?

`/model/validation` отдаёт `comparisons` отдельно от `metrics`. Пары «прогноз — факт» берутся из
`chart_data.json` и сверяются со строками `train_dataset.csv` с точностью 0,00051 мм по ключам,
историческим трубам и датам разбиения. При совпадении серия получает `status=available`,
точки `pipe_id,segment_id,observed_mm,forecast_mm` и пересчитанные r² и MAE. Серия, которая не
совпала с разбиением, получает `status=source_mismatch` без точек и метрик, и интерфейс объясняет,
почему графика нет.
